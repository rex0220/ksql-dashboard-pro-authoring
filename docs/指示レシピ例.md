# ダッシュボード作成の指示レシピ例

AI への指示は日本語の文章で十分です。ここでは「そのまま真似できる」指示例を
構成パターン別に載せます。共通のコツ:

- **アプリは番号で**指定(アプリの URL `/k/番号/` で確認)
- **置き場は一覧(ビュー)名で**指定 — 生成された設定はインポート時に一覧名で照合されます
- **保存先のファイル名と、新規か更新かを指示**します — 新規なら「settings/◯◯.json に保存して」、
  既存の変更なら「settings/◯◯.json を更新して」。曖昧だと意図しない上書きや
  二重ファイルのもとになります。**ファイル名の体系は利用者側で決めて統一**してください
  (考え方は [settings/README.md](../settings/README.md))
- 迷ったら細かく書かなくてよい — AI がフィールド定義と実データを見てから提案してきます

## 0. 事前準備(kintone 側)

AI は kintone の設定を**変更できません**(読み取り専用)。一覧(ビュー)は先に人が作ります。

- **全面のダッシュボードを置くなら、カスタマイズ形式の一覧を手作業で先に追加**します:
  アプリの設定 → 一覧 → +(追加)→ レコード一覧の表示形式で**「カスタマイズ」**を選択 →
  HTML は空のまま保存 → **アプリを更新**。名前の例: `【全社】ダッシュボード`
  (画像付きの手順は [SFA ハンズオン記事](https://qiita.com/rex0220/items/394e8561d4f7fc5c3051) にあります)
- 置き場の使い分け(ダッシュボードは一覧の上部に出て、レコードの表を下へ押し下げます):

  | 置き場 | 主役 | 置くもの |
  | :--- | :--- | :--- |
  | 標準の一覧 | レコード | 共通ダッシュボードで KPI 横 1 列(1 段)まで |
  | カスタマイズ形式の一覧 | ダッシュボード | 全面ダッシュボード。何段でも |
  | 作業用の絞り込み一覧 | レコード | 置かない |

## 1. 作成指示の例

### 1.1 シンプル(タブなし・全一覧共通のサマリー 1 段)

```
アプリ 4149(案件管理)の共通ダッシュボードに、KPI カードを横 1 列で 4 枚:
今月の受注金額(目標 5,000 万・達成率バー付き)、今月の受注件数、商談中の件数、受注率。
標準の一覧の上に出るので、高さは 1 段(3 行)に収めて。
settings/案件管理-共通サマリー.json に保存して。
```

### 1.2 全面ダッシュボード(タブなし・カスタマイズ一覧)

```
アプリ 4149(案件管理)の一覧「【全社】ダッシュボード」に、全面のダッシュボードを作って。
上段: KPI 3 枚(今月の受注金額・受注率・平均単価)
中段: フェーズ別売上の棒グラフ(値ラベル付き)と、会社別売上の上位 5 + その他(横棒)
下段: 受注予定日が今月の案件明細(表・金額の大きい順・レコードへのリンク付き)
金額は万円表記で。settings/案件管理-全社ダッシュボード.json に保存して。
```

### 1.3 タブあり

```
アプリ 4149(案件管理)の一覧「【全社】ダッシュボード」に、タブ 3 つのダッシュボードを:
- タブ「サマリー」: KPI 4 枚と、月別受注金額の推移(折れ線)
- タブ「分析」: フェーズ別・担当者別・商品分類別の売上棒グラフ 3 枚
- タブ「明細」: 商談中の案件一覧(表・受注予定日の近い順)
settings/案件管理-全社ダッシュボード.json に保存して。
```

1 タブに置けるペインは最大 12 枚です。多くなりそうならタブを分けてください。

### 1.4 期間コントロールあり(閲覧者が期間を切り替え)

```
アプリ 4149(案件管理)の一覧「【全社】ダッシュボード」に、期間を切り替えられる
ダッシュボードを作って。
期間コントロールの選択肢は 今月・前月・今年・去年・期間指定。既定は今月。
ペインは、受注金額 KPI、フェーズ別売上の棒グラフ、受注予定の明細表の 3 枚。
すべて受注予定日で期間に追従させて。
settings/案件管理-期間ダッシュボード.json に保存して。
```

タブごとに期間の扱いを変えることもできます:
「タブ『月次』は今月・前月だけ、タブ『任意期間』は期間指定のみ(初期値は過去 1 か月)にして」

## 2. 作成後の変更・追加の指示例

変更は「**対象の settings/ ファイル名** + 変更内容 + **更新して**」を伝えます
(既存ファイルの更新か、別ダッシュボードとしての新規作成かを曖昧にしない)。
設定画面(GUI)で直した内容を取り込みたいときは、エクスポートした JSON を渡します。

- **ペインを追加**:
  「settings/案件管理-全社ダッシュボード.json に、失注理由の円グラフを追加して。
  置き場所が足りなければレイアウトは調整してよい」
- **見た目を変更**:
  「受注金額 KPI に条件付きカラーを付けて: 達成率 100% 以上は緑、80% 未満は赤」
- **期間の選択肢を変更**:
  「期間コントロールに『今週』を追加して、既定を期間指定(過去 1 か月〜当月末)に変えて」
- **タブを追加**:
  「タブ『商品別』を追加して、商品分類別の売上棒グラフと明細表を置いて」
- **絞り込み条件を変更**:
  「明細の表を、商談中フェーズの案件だけに絞って」
- **GUI で直した設定を git へ戻す**:
  「この export JSON を settings/ の正として上書きして」(ファイルを渡すか貼り付け)
- **別アプリ用に複製**:
  「同じ構成をアプリ 4200(案件管理・第2営業部)用にも作って。
  論理アプリ名(LAPP_)で環境非依存にして」

変更後も封筒形式のまま上書き保存されるので、git の diff で「何が変わったか」を
確認してからインポートしてください。

## 3. うまくいかないときの指示例

- 「このペインだけ『SQL にエラー』と出る。設定画面の構文チェックの内容はこれ: (貼り付け)」
- 「数字が実際より少ない。取得上限に掛かっていないか確認して」
- 「アプリ番号がテスト環境と本番で違う。logicalApps 方式に書き換えて」
