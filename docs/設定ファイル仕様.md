## 0.1 エクスポートの封筒

設定画面のエクスポートは、設定本体を**封筒**で包んで出力する(既存有償プラグイン・無償版と
同じ流儀)。ファイル名は `ksql-dashboard-pro-app<アプリID>-<YYYYMMDD>-<HHMMSS>.json`。

```jsonc
{
  "date": "2026-07-31 10:24:35",
  "pluginName": "kSQL Dashboard Pro",
  "pluginVersion": "1",
  "engineVersion": "3.35.0",
  "pluginId": "…",
  "appId": 4149,
  "appName": "案件管理",
  "sqlApps": [                       // SQL が参照しているアプリの一覧
    { "appId": 4149, "appName": "案件管理" },
    { "appId": 4148, "appName": "顧客管理", "logicalName": "顧客管理" }  // LAPP_ 参照
  ],
  "config": { /* 設定本体(§1 のルート構造) */ }
}
```

- **インポートは封筒の有無どちらも受け付ける**(封筒は自動で剥がされる)。
  手書きする場合は本体(§1)だけでよい
- インポート時は封筒のメタ情報(出力日時・プラグイン・アプリ)を**確認ダイアログ**に
  表示し、承認後に取り込む。別アプリ・別環境の控えの取り違えを防ぐため
- 封筒のメタ情報は表示用で、**検証には使わない**(取り込みの可否は本体の検証で決まる)
- **アプリ番号の変換**: 確認ダイアログの「アプリ番号を変換する」で、SQL 中の
  `APPnnn`(`APPnnn$テーブル` の親参照を含む)を指定した番号へ一括変換してから
  取り込める。変換対象の一覧は**ファイル内 SQL の走査**から作るため、封筒の無い
  旧ファイル・手書きファイルでも使える(`sqlApps` は元アプリ名の表示にだけ使う)。
  構文解析はしない割り切りのため、SQL 文字列リテラル内の `APPnnn` も置換される
- **このビューへ取り込む**: 取り込むダッシュボード(複数入りのファイル)と
  **取り込み先の一覧**も確認ダイアログ内で選ぶ。先に左ナビでビューを選んでおく必要はない。
  このとき APPID 変換の対象は**選んだダッシュボードの範囲だけ**になる(全置換は全体)
- **論理アプリの割り当て**: SQL が `LAPP_<名前>` を使う設定では、確認ダイアログで
  **論理名の扱い**を選べる:
  ①**そのまま取り込む**(ファイルの対応表をそのまま。同一環境の別アプリ設定向け)
  ②**取り込み先の定義を優先する**(全置換のみ。対応表はこの環境の現在の定義を保ち、
  無い名前だけファイルから補う。テスト設定を運用アプリへ入れるケース向け)
  ③**割り当てを指定する**(SQL は無傷のまま番号だけこの環境に合わせる。別環境への移行向け。
  アプリ番号の変換と違い**再エクスポートしても環境依存が戻らない**)
  ④**論理名を取り込まない**(ファイルの対応表で `APP<番号>` へ展開してから取り込む。
  対応表は取り込まない。展開後の番号は「アプリ番号の変換」でさらに置き換えられる)。
  ビューへ取り込むでは**取り込み先に定義済みの名前は常に取り込み先優先**(②相当が既定のため
  選択肢には出ない)

## 0. まず読むべき 5 点

1. `schemaVersion` は **`2` ちょうど**、`edition` は **`"pro"`** 固定。違うと読み込めない。
2. **1 ダッシュボードのペインは最大 12 枚**、グリッドは **60 カラム**で `x + w ≤ 60`。
3. `layout[].i` と `panes[].id` は**別々の配列で管理する。両方を必ず 1:1 で書く**
   (バリデータは対応を検査しない。§9)。
4. `options` は**未知キーを許す**(誤ったキー名はエラーにならず、黙って無視される)。
   ただし**既知キーの形は検査される**(`bars` に配列以外を書く等はインポートエラー)。
   本書のキー名を正確に使うこと。
5. **SQL はプラグインで動くサブセットに限る**(§8)。CLI / MCP 専用構文はペインでエラーになる。

## 1. ルート構造

```jsonc
{
  "schemaVersion": 2,          // 必須。2 固定
  "edition": "pro",            // 必須。"pro" 固定
  "views": {                   // 必須。一覧(ビュー)ID → ViewSettings
    "13311757": { /* ViewSettings */ }
  },
  "common": {                  // 必須(空オブジェクト可)
    "theme": "light",          // 省略可
    "textScale": "xlarge",     // 省略可。省略 = 標準(110%)
    "csvExport": true,         // 省略可。省略 = 無効
    "view": { /* ViewSettings */ }   // 省略可。共通ダッシュボード
  },
  "deployOnSave": true,        // 省略可。省略 = 有効
  "knownViews": ["20", "31"],  // 省略可。文字列配列
  "logicalApps": {             // 省略可。論理アプリ名 → アプリ番号
    "顧客管理": 4148,
    "案件管理": 4149
  }
}
```

| キー | 型 | 必須 | 説明 |
| :--- | :--- | :--: | :--- |
| `schemaVersion` | `2` | ✅ | これ以外は読み込み拒否 |
| `edition` | `"pro"` | ✅ | |
| `views` | object | ✅ | キーは一覧 ID(文字列)。**空 `{}` でよい** |
| `common.theme` | `"light"｜"cool"｜"warm"｜"dark"｜"midnight"｜"black"` | | `dark` は「グレー」の意 |
| `common.textScale` | `"normal"｜"large"｜"xlarge"｜"max"` | large | **表示サイズ**。小 100 / **標準 110(既定)** / 大 125 / 特大 150%。文字と行高の両方に掛かる。利用者は一覧画面のヘッダーからアプリ単位で上書きでき、その選択が優先される |
| `common.csvExport` | boolean | | 一覧画面の CSV ダウンロード許可 |
| `common.view` | ViewSettings | | **共通ダッシュボード**。個別設定の無い一覧に適用される |
| `deployOnSave` | boolean | | 保存時にアプリの運用環境へ反映するか |
| `knownViews` | string[] | | 保存時点で存在した一覧 ID |
| `logicalApps` | object | | **論理アプリ名 → アプリ番号**。SQL の `LAPP_<名前>` をこの表で解決する。名前は日本語可(空白・`$`・`@`・引用符は不可、64 文字まで。数字・`_` 開始不可)。番号は 1 以上の整数。対応表は**ダッシュボード全体で 1 つ** |

> **迷ったら `common.view` に書く。** 一覧 ID は環境ごとに異なるため、
> `views` を使うと移植時に書き換えが必要になる。共通ダッシュボードなら全一覧に出る。
>
> `views` を移植する場合は **`viewName`(一覧名)** を各エントリーへ書いておく。
> インポート先に同じ viewId が無くても、**同名の一覧(完全一致・一意)へ自動で
> 割り当てられる**。設定画面のエクスポートは自動で付与する。同名が 0 件・複数件の
> エントリーは取り込まれず、インポート時の通知に一覧名が列挙される。

## 2. ViewSettings(1 つのダッシュボード)

```jsonc
{
  "name": "営業ダッシュボード",   // 省略可
  "layout": [ /* LayoutItem[] */ ],   // 必須(配列。空可)
  "panes":  [ /* PaneSettings[] */ ], // 必須(配列。最大 12)
  "enabled": true,              // 省略可。省略 = 有効
  "source": "individual",       // 省略可。個別ビューのみ
  "refreshSec": 1800,           // 省略可。0/省略 = 自動更新なし(600 の倍数・最小 600)
  "initialCollapsed": false,    // 省略可
  "tabs": [ /* DashboardTab[] */ ],   // 省略可(§2.1)。あるときは layout/panes を見ない
  "controls": []                // 変数コントロールバー(§2.2)。使わなければ書かない
}
```

| キー | 型 | 必須 | 説明 |
| :--- | :--- | :--: | :--- |
| `name` | string | | 一覧画面ヘッダー・フル画面に表示 |
| `viewName` | string | | **一覧名(エクスポート専用メタ)**。インポート先に viewId が無いとき、同名の一覧へ割り当てる手掛かり。kintone への保存形には含まれない(保存時に除去) |
| `layout` | LayoutItem[] | ✅ | §3 |
| `panes` | PaneSettings[] | ✅ | §4。**12 枚まで。`id` は重複不可** |
| `enabled` | boolean | | `false` でこのダッシュボードを非表示 |
| `source` | `"common"｜"individual"` | | `common` = 個別定義を保持したまま共通を表示 |
| `refreshSec` | number(≥0) | | 自動更新間隔(秒)。**最短 600(10 分)・600 の倍数**。設定画面の指定は分。折りたたみ中は停止。**範囲外の値は読み込み時に切り上げで丸められる**(`1` と書いても 600 として動く) |
| `initialCollapsed` | boolean | | 初期は折りたたむ。利用者の切替が優先 |
| `tabs` | DashboardTab[] | | タブ(§2.1)。**省略 = タブなし** |
| `controls` | ControlSettings[] | | **変数コントロールバー**。§2.2 |

### 2.2 ControlSettings(変数コントロール)

一覧画面のダッシュボード上部に期間の切り替えバーを出す。選択肢は
**kintone の相対日付関数と 1:1**(今日・昨日・明日・今週・先週・来週・今月・前月・来月・
今年・去年・来年)+ **期間指定**(任意の開始〜終了)で、`presets` で必要なものだけに絞れる
(**期間指定のみ**の構成も可)。表示は横並びボタンまたはドロップダウン(`display`。
省略 = 選択肢数で自動)。閲覧者の選択はブラウザに記憶される。

**定義は 2 か所に置ける**:

- `ViewSettings.controls` — **全タブ共通**(バーに常に出る)
- `DashboardTab.controls` — **そのタブ専用**(表示中タブでだけ出る。同名 `var` はタブ側が優先)

タブごとに SQL の書き方を揃える使い分けができる — 例:「プリセットのタブ」は単一変数形
(`= @period`)、「期間指定のタブ」は `presets: ["custom"]` のコントロール + 範囲形
(`>= @range_from AND < @range_to_next`)で書く。

```jsonc
"controls": [
  { "var": "period", "type": "date", "label": "対象期間", "default": "thisMonth",
    "presets": ["thisMonth", "lastMonth", "thisYear", "lastYear"] }  // 4 個 → 自動で横並び
]
```

| キー | 型 | 必須 | 説明 |
| :--- | :--- | :--: | :--- |
| `var` | string | ✅ | 変数名。**半角英字始まりの英数字・`_`(64 文字以内)**。日本語不可(エンジン仕様) |
| `type` | `"date"｜"string"｜"number"` | ✅ | `date` = 期間バー(下記)。`string` / `number` = 入力欄、`options` があればドロップダウン |
| `label` | string | ✅ | バーに表示する名前(日本語可) |
| `default` | string | | バーの初期選択: プリセットキー(`"today"`〜`"nextYear"`)または **`"custom"`**(期間指定で開く — 初期値は `customFrom` / `customTo`)。省略 = `thisMonth` |
| `presets` | string[] | | バーに出す選択肢の**部分集合**(上のプリセットキー + `"custom"`)。省略 = 全部。並びは正規順に整列される。例: `["thisMonth","lastMonth","thisYear","lastYear"]` |
| `display` | `"buttons"｜"dropdown"` | | バーの表示形式。省略 = **自動**(選択肢 5 個以下なら横並びボタン、多ければドロップダウン) |
| `customFrom` | string | | **期間指定(custom)の開始日の既定**(相対トークン)。例: `"today-1m"`(当日の 1 か月前)、`"thisMonthStart"`(当月の初日)。省略 = 空欄 |
| `customTo` | string | | **期間指定(custom)の終了日の既定**。例: `"thisMonthEnd"`(当月の末日)、`"nextMonthEnd"`(来月末)。省略 = 空欄 |
| `options` | string[] | | **`string` / `number` のみ。固定の選択肢**(最大 50)。指定するとドロップダウンになり、先頭に「指定なし」(空文字)が入る。省略・空 = 自由入力 |
| `optionsSql` | string | | **`string` / `number` のみ。選択肢を SQL で作る**(下記)。1 列目 = 値 / 2 列目 = 表示名。設定読込時に 1 回だけ実行。`options` より優先 |

`customFrom` / `customTo` のトークン文法: `today±N(d|w|m|y)`(当日からの相対。例 `today-3m`)と
`(this|last|next)(Week|Month|Year)(Start|End)`(例 `thisMonthStart` / `nextMonthEnd`)。
固定日付ではなく**開くたびに解決される相対ルール**なので、設定が古くならない。
利用者が日付を入力すればそちらが優先(「既定に戻す」で初期値へ戻る)。

**SQL からの参照** — date コントロール 1 個につき 4 変数が供給される。

**推奨: 単一変数形**(kintone 関数がそのまま入る)

```sql
SELECT 商談フェーズ, SUM(売上) AS 売上
FROM APP4149
WHERE 受注予定日 = @period
GROUP BY 商談フェーズ
```

- プリセット選択時、`@<var>` には **kintone の相対日付関数(`THIS_MONTH()` 等)が
  関数として**注入され、kintone サーバー評価で押し下がる**。**日時フィールドの境界・タイムゾーンも kintone 任せ**で、
  `受注予定日 = THIS_MONTH()` と直接書いたのと同じ意味論になる
- **期間指定(任意区間)は関数で表せない** — 閲覧者が期間指定を選んだとき、
  単一変数形のペインは**既定プリセットで動く**。期間指定に追従させたいペインは範囲形で書く

**範囲形**(期間指定 = 任意区間に追従する)— **半開区間**で書く(B113 回答)

```sql
WHERE 受注予定日 >= @period_from AND 受注予定日 < @period_to_next
```

- `@<var>_from`(開始日)/ `@<var>_to_next`(**終了日の翌日**)。いずれも YYYY-MM-DD の
  日付リテラル(クライアント解決)。週は日曜始まり
- **半開区間(`>=` と `<`)なら日付・日時フィールドで同じ書き方**になり、kintone の
  タイムゾーン設定にも依存しない(エンジン実測 — `<= 終了日` は日時フィールドで
  終端日の日中を取りこぼす)
- `@<var>_to`(終了日そのもの)も供給される。日付フィールドで `<= @<var>_to` と
  書いても動くが、日時フィールドに流用できないため半開区間を推奨

**共通の規則**

- `DECLARE` は書かない — プラグインが既定値で自動前置する(単一変数は
  `DECLARE @<var> RELATIVE_DATE = …`、範囲形は文字列リテラル。自前の `DECLARE @x` があれば触らない)
- ホワイトリスト外の値は kintone API を呼ぶ前に名前入りエラー(fail-closed)。
  値束縛のため **SQL インジェクションは起きない**
- **変数を参照しないペインは切り替えの影響を受けない**(再実行されない)
- 常に固定期間でよいペインは、従来どおり `THIS_MONTH()` などを直接書く(変数化しない)
- 注意: 自前で `RELATIVE_DATE` なしの `DECLARE @p = TODAY()` と書くと**クライアント評価の
  リテラル**になり、kintone サーバー評価とは別物(エンジン言語リファレンス参照)
- 設定画面のプレビュー・構文チェック・EXPLAIN は**既定値**で実行される

#### string / number コントロール

閲覧者に**文字列・数値を 1 つ入力させる**。供給されるのは `@<var>` **1 本だけ**で、
範囲形(`_from` / `_to` / `_to_next`)は date 専用。

```jsonc
"controls": [
  { "var": "kw",   "type": "string", "label": "顧客名" },
  { "var": "goal", "type": "number", "label": "目標金額", "default": "5000000" },
  { "var": "area", "type": "string", "label": "エリア", "options": ["東日本", "西日本"] }
]
```

```sql
SELECT 顧客名, SUM(受注金額) AS 売上 FROM APP100
WHERE 顧客名 KLIKE @kw          -- 文字列(部分一致は KLIKE の右辺へ)
GROUP BY 顧客名

SELECT SUM(受注金額) AS メイン値, @goal AS 目標値 FROM APP100   -- 数値(達成率の what-if)
```

- **`options` を書くとドロップダウン**になり、先頭に「指定なし」(空文字)が入る。
  省略すれば自由入力
- **未入力・数値にならない入力は変数を供給しない** — そのペインは `DECLARE` の既定値で動く。
  自由入力に既定値を持たせたいときは `default` を書く
- **ユーザー選択フィールドの絞り込みには使わない。** 照合は**表示名ではなく code** で、
  存在しない値を渡すと 0 件ではなく **kintone API エラー**になる(実測)。
  打ち間違いがそのままエラーになるため、自由入力とは相性が悪い
- 値束縛なので **SQL インジェクションは起きない**(date と同じ)

##### 選択肢を SQL で作る(`optionsSql`)

固定リストで足りないときは **SQL で選択肢を作れる**。**設定読込時に 1 回だけ**実行し、
ペインと同じ read-only 経路・同じ共有キャッシュを通る。

| 決まりごと | 内容 |
| :--- | :--- |
| 列の使い方 | **1 列目 = 値**(SQL へ注入)/ **2 列目 = 表示名**(省略なら値をそのまま出す) |
| 上限 | **100 件**。超えたら打ち切り、バーに「上位 100 件のみ」と出す |
| 空の値 | 落とす(「指定なし」と区別が付かないため) |
| 重複 | 最初の 1 件だけ残す(`DISTINCT` を書き忘れても壊れない) |
| 取得できないとき | バーに注記を出し、**自由入力へ落とす**(バーごと使えなくなるより良い) |

```jsonc
{ "var": "owner", "type": "string", "label": "担当者",
  "optionsSql": "SELECT 担当者コード, 担当者名 FROM APP200 ORDER BY 担当者名" }
```

**担当者はマスタアプリ経由を推奨する。**理由は 2 つある。

- **ユーザー選択フィールドからは選択肢を取れない。** `SELECT DISTINCT ユーザー選択` が返すのは
  表示名でも code でもなく、`[{"code":"rex0220","name":"開発太郎"}]` という**生の JSON**(実測)
- **注入する値は code でなければならない。** 表示名を渡すと 0 件ではなく **kintone API エラー**
  になる(`GAIA_IL26`)。だから **2 列(値 = code / ラベル = 表示名)**に分ける

**絞らなければ対象アプリを全件読む。** `SELECT DISTINCT 部署名 FROM APP88` のように `WHERE` がないと、
そのアプリの**全レコードを取得する**(約 500 件 = REST 1 回。5,000 件なら 10 回)。
重複除去はエンジン側の処理なので、**`DISTINCT` を書いても取得件数は減らない**。
実行は設定読込時の 1 回きりだが、**ダッシュボードが出るまでの待ち時間**になる。

- 選択肢は**マスタアプリから取る**のが基本。件数が少なく GET 1 回で済み、組織変更にもマスタの更新だけで追従できる
- トランザクション側のアプリから取るなら、`WHERE 作成日時 >= LAST_YEAR()` のように
  **期間で走査を絞る**(押し下げが効き、REST 側で絞られる)
- ペインが**同じアプリを同じ条件で**読んでいれば共有キャッシュで合流し、追加の取得は起きない
- 実際の取得量は**ペイン設定の実行計画(EXPLAIN)**で確認できる(`fetch:` の行)

**固定の選択肢に表示名を付けたいなら、リテラルを `UNION ALL` でつなぐ**(実測)。
`FROM` がないのでレコードは 1 件も読まない。`options`(カンマ区切り)は値だけなので、
**値と表示名を分けたい固定リストはこの形が唯一の手段**になる。

```jsonc
{ "var": "plan", "type": "string", "label": "提案プラン",
  "optionsSql": "SELECT 'A' AS 値, 'Aプラン' AS 表示名 UNION ALL SELECT 'B', 'Bプラン'" }
```

| 用途 | 書き方 | 取得 |
| :--- | :--- | :--- |
| 値だけの固定リスト | `options: ["Aプラン", "Bプラン"]` | なし |
| 値と表示名が違う固定リスト | `optionsSql` にリテラルの `UNION ALL` | **なし** |
| レコードから作る動的リスト | `optionsSql` に `SELECT … FROM APPn WHERE …` | あり(絞らなければ全件) |

### 2.1 DashboardTab(タブ)

1 つのダッシュボードを最大 **6 枚**のタブに分ける。

```jsonc
"tabs": [
  { "id": "tab1", "name": "",     "layout": [ /* … */ ], "panes": [ /* … */ ] },
  { "id": "tab2", "name": "売上", "layout": [ /* … */ ], "panes": [ /* … */ ] }
]
```

| キー | 型 | 必須 | 説明 |
| :--- | :--- | :--: | :--- |
| `id` | string | ✅ | ビュー内で重複不可。**並べ替えても変えない**(利用者が選んだタブの記憶が外れる) |
| `name` | string | | 見出し。空なら 1 枚目は**ダッシュボード名**、以降は「タブ n」を表示する |
| `layout` | LayoutItem[] | ✅ | §3 |
| `panes` | PaneSettings[] | ✅ | §4。**1 タブあたり 12 枚まで** |
| `controls` | ControlSettings[] | | **このタブ専用**の変数コントロール(§2.2)。ビュー共通に追加され、同名 `var` はタブ側が優先 |

**`tabs` があるときは、ビュー直下の `layout` / `panes` を見ない**(空配列にしておく)。
両方を正にすると必ずずれるため。

**ペイン `id` はビュー内(全タブ)で一意**にする。タブごとに採番すると、レイアウトのキーが
衝突し、選択状態や「元に戻す」が対象を取り違える。

設定画面で保存すると、**タブが 1 枚で名前も空のときは `tabs` を書かず**に
`layout` / `panes` へ畳む(タブを使わない設定に項目を増やさないため)。
名前を付けている場合は畳まない。

## 3. LayoutItem(配置)

```jsonc
{ "i": "pane1", "x": 0, "y": 0, "w": 20, "h": 5 }
```

| キー | 型 | 制約 |
| :--- | :--- | :--- |
| `i` | string | **対応する `panes[].id` と同じ値**。空文字不可。**同じ `layout` 内で重複不可** |
| `x` | number | **0 以上の整数**。左端からのカラム位置 |
| `y` | number | **0 以上の整数**。上からの行位置 |
| `w` | number | **1 以上の整数**。**`x + w ≤ 60`(超えるとエラー)** |
| `h` | number | **1 以上の整数**。行数。**`y + h ≤ 2000`**(巨大な値は描画フリーズ防止で弾く) |

**グリッドの寸法**

- 横は **60 カラム**。全幅 = `w: 60`、半分 = `w: 30`、1/3 = `w: 20`
- 縦は 1 行 = **40px**、ペイン間隔 = **10px**。`h: 5` ≒ 240px
- 基準幅 1280px に対して比例スケールする(画面幅が変わっても縦横比は保たれる)
- コンテナ幅 1024px 未満は 1 カラム縦積みへ自動フォールバック

**目安の高さ**

| ペイン | 推奨 `h` |
| :--- | :--- |
| KPI カード | 3 |
| KPI タイル・マークダウン | 3〜4 |
| グラフ | 5〜6 |
| 表 | 5〜8 |

**配置例(60 カラム・3 段)**

```jsonc
[
  { "i": "pane1", "x":  0, "y": 0, "w": 14, "h": 3 },
  { "i": "pane2", "x": 14, "y": 0, "w": 26, "h": 3 },
  { "i": "pane3", "x": 40, "y": 0, "w": 20, "h": 3 },
  { "i": "pane4", "x":  0, "y": 3, "w": 20, "h": 5 },
  { "i": "pane5", "x": 20, "y": 3, "w": 20, "h": 5 },
  { "i": "pane6", "x": 40, "y": 3, "w": 20, "h": 5 },
  { "i": "pane7", "x":  0, "y": 8, "w": 60, "h": 6 }
]
```

> 重なりは検査されない。同じ `x,y` 帯に複数のペインを置くと重なって描画される。

## 6. `options`(表示タイプ別)

> **重要**: `options` はバリデータを素通りする。キー名の誤り・型の誤りは
> **エラーにならず無視される**。動かないときはまずキー名を疑うこと。

### 6.0 全タイプ共通

| キー | 型 | 既定 | 説明 |
| :--- | :--- | :--- | :--- |
| `description` | string | | **閲覧者向けの説明**。一覧画面でタイトル横の ⓘ からポップオーバー表示。サニタイズ済み Markdown 可。概要 Markdownにも掲載される |
| `descWidth` | `"small"｜"medium"｜"large"` | medium | 説明ポップオーバーの幅(小 240 / 中 360 / 大 560px)。表を書くときは large が読みやすい。ポップオーバーはペインの外へはみ出して表示される |
| `pieStartAngle` | number | 0 | 円・ドーナツの開始角度。**12 時から時計回りに何度**ずらすか(0 = 12 時、90 = 3 時)。**既定は 12 時から時計回り**(2026-08-01 に Recharts 既定の 3 時・反時計回りから変更 — 既存の円・ドーナツは見た目が回転する。数値は不変) |
| `maxRecords` | number | 10000 | 取得上限。**500〜50,000 に丸められる**。10,000 超は取得に時間がかかる(約 500 件 = 1 リクエスト)。まず WHERE・kintone 関数で絞るのが先 |
| `tempTableMaxRows` | number | 10000 | 一時テーブル 1 表あたりの実体化行数。**500〜50,000 に丸められる**(取得上限に揃えてある)。超過は常にエラー。複文で `CREATE TEMP TABLE` を使うときだけ効く(§8) |
| `links` | LinkSpec[] | | **静的リンク**。ヘッダーのアイコンから遷移する導線。**最大 5**。1 個ならアイコン直押し、2 個以上でメニュー。設定画面のプレビューでは遷移しない |

**LinkSpec** — `{ label, app, view? }` または `{ label, url }`(`app` と `url` は排他)

| キー | 型 | 説明 |
| :--- | :--- | :--- |
| `label` | string | 必須(1〜40 文字)。メニュー・title に表示 |
| `app` | number | 遷移先アプリ番号。**こちらを推奨** — ゲストスペース配下・環境移行でも壊れない。インポート時の APPID 変換(§7.2)は SQL と同じ対応表で `app` も書き換える |
| `view` | number | 遷移先ビュー ID(任意。`app` と組み合わせ)。**環境依存**のため移行後は要確認(変換対象にできない) |
| `url` | string | 生 URL(逃げ道)。`https://` / `http://` または `/` 始まりの同一オリジンパスのみ。`javascript:` 等のスキームは保存時・描画時の両方で拒否される |

使い分け: **ダッシュボード全体の案内はマークダウンペイン、個別ペインの導線はリンク設定。**

### 6.1 `kpi`

| キー | 型 | 既定 | 説明 |
| :--- | :--- | :--- | :--- |
| `fontSize` | `"large"｜"xlarge"` | large | メイン値の文字サイズ |
| `format` | NumberFormat(`kind` 抜き。§7) | | メイン値の数値書式 |
| `invertDelta` | boolean | false | 増加を赤に(コスト系指標向け) |
| `goalBar` | boolean | false | 達成率をプログレスバーで表示 |
| `multi` | boolean | false | **各行をタイルで並べる** |
| `maxTiles` | number | 8 | `multi` 時の最大タイル数(超過は「他 N 件」) |
| `rules` | KpiRule[] | | 条件付きカラー。**最大 10** |
| `kpi` | KpiMapping | | 列の明示割り当て |

**KpiMapping** — 省略時は予約列名 → 1 列目の順で自動解決される。

```jsonc
"kpi": { "value": "売上", "title": "区分", "base": "前月", "target": "目標", "delta": "差", "rate": "達成" }
```

**KPI 予約列名**(SQL のエイリアスをこの名前にすると自動認識。大文字小文字を区別しない)

| 役割 | 予約列名 | 効果 |
| :--- | :--- | :--- |
| メイン値 | `メイン値` / `value` / `main` | 巨大表示。**未解決なら 1 列目** |
| タイトル | `タイトル` / `title` | カード見出し(`title` 設定が優先) |
| 比較値 | `比較値` / `delta` / `comparison` | そのまま増減表示 |
| 基準値 | `基準値` / `前月値` / `base` / `previous` | メイン値との**増減率を自動計算** |
| 目標値 | `目標値` / `target` / `goal` | **達成率を自動計算** |
| 達成率 | `達成率` / `rate` / `achievement` | サブ情報として表示 |

**KpiRule**

```jsonc
{ "target": "main", "op": ">=", "value": 100, "tone": "good", "apply": "border" }
```

| キー | 値 | 必須 |
| :--- | :--- | :--: |
| `target` | `"main"｜"rate"` | ✅ |
| `op` | `">="｜">"｜"<="｜"<"｜"="｜"!="` | ✅ |
| `value` | number | ✅ |
| `tone` | `"good"｜"warn"｜"crit"` | ✅ |
| `apply` | `"text"(既定)｜"background"｜"border"` | |

上から順に評価し、**同じ `apply` は後のルールが優先**(後勝ち)。

### 6.2 `table`

| キー | 型 | 既定 | 説明 |
| :--- | :--- | :--- | :--- |
| `columns` | `Record<列名, TableColumnOption>` | | 列ごとの設定 |
| `columnGroups` | `{label, columns[]}[]` | | マルチヘッダー(2 階層) |
| `totals` | `Record<列名, TotalKind>` | | 集計行。`"sum"｜"avg"｜"count"｜"max"｜"min"` |
| `rules` | TableRule[] | | 条件付き書式。**最大 20** |
| `density` | `"normal"｜"compact"` | normal | 表示密度 |
| `fontSize` | `"small"｜"normal"｜"large"｜"xlarge"` | normal | 文字サイズ(行高も追従) |
| `overflow` | `"virtual"｜"pages"` | virtual | 1,000 行超の描画方式 |
| `initialSort` | `{column, desc}[]` | | 初期ソート |
| `topN` | number | | 上位 N + その他。**上から** N 行を残し、残りを 1 行の「その他(件数)」にまとめる。無指定なら全行 |
| `rowNumbers` | boolean | false | 先頭に行番号列。番号は**表示順**で、並べ替えると振り直す。「その他」行・集計行には付かない。CSV 出力には含まれない。同順位を 1, 1, 3 と表現したいときは SQL の RANK() を使う |
| `unitInHeader` | boolean | false | 単位を列見出しにまとめる。フォーマットに表示スケール(千・万・百万)を持つ数値列で、セルは素の数字・見出しは「売上(万)」になる。集計行も素の数字。グラフ `unitOnAxis`の表版で、並べたグラフと表示が揃う。CSV は生値のまま |

**並べ替えはしない。** 順序は SQL の `ORDER BY` と `initialSort` で決める。
表は列が複数あって「どの列で順位を付けるか」が一意に決まらないため、こちらで並べ替えない
(グラフは全系列の合計で一意に決まるので値の降順にする)。

「その他」行の各列は**集計行と同じ集計**で埋める(`totals` の指定に従う。文字列の列は空)。
`totals` に指定の無い数値列の既定は、`totals` の設定有無で変わる:

- `totals` を **1 列でも設定した表** — 指定の無い数値列は**空欄**。順位・達成率・単価のような
  合算に意味の無い列へ誤った合計を出さないため(「集計したい列を宣言する」方式)
- `totals` が**未設定の表** — 従来どおり全数値列を合計

**集計行そのものは元の全行から計算する**ので、まとめても合計・平均は変わらない。

**TableColumnOption**

```jsonc
"columns": {
  "売上":       { "align": "right", "format": { "kind": "number", "prefix": "¥", "thousandSep": true, "decimals": 0 } },
  "受注予定日": { "width": 120, "align": "center", "format": { "kind": "date", "pattern": "YYYY/MM/DD" } },
  "$id":        { "hidden": true }
}
```

| キー | 型 | 説明 |
| :--- | :--- | :--- |
| `hidden` | boolean | 非表示。**`$id` を隠してもレコード遷移アイコンは残る** |
| `label` | string | 表示名(SQL エイリアスと別にしたいとき) |
| `width` | number | px。省略 = 自動 |
| `align` | `"left"｜"center"｜"right"` | 省略時は型から自動 |
| `format` | FormatSpec(§7) | **`kind` が必要**(KPI・グラフとは異なる) |
| `wrap` | boolean | 折り返し。省略時は省略記号 + ツールチップ |

**TableRule**

```jsonc
[
  { "kind": "threshold", "column": "売上", "op": ">=", "value": 6000000, "tone": "good" },
  { "kind": "threshold", "column": "フェーズ", "op": "=", "value": "内示", "tone": "warn", "scope": "row" },
  { "kind": "heatmap",   "column": "売上" }
]
```

| キー | 値 |
| :--- | :--- |
| `kind` | `"threshold"` または `"heatmap"` |
| `column` | 列名(必須) |
| `op` | `">="｜">"｜"<="｜"<"｜"="｜"!="｜"empty"｜"notEmpty"`(threshold のみ) |
| `value` | number または string(`empty`/`notEmpty` では不要) |
| `tone` | `"good"｜"warn"｜"crit"`(threshold のみ) |
| `scope` | `"cell"(既定)｜"row"` |
| `bold` | boolean |

`heatmap` は `kind` と `column` のみ(4 段階の色分け)。

### 6.3 グラフ(`bar` / `barH` / `barStacked` / `barHStacked` / `line` / `area` / `pie` / `donut` / `combo`)

| キー | 型 | 既定 | 適用 |
| :--- | :--- | :--- | :--- |
| `mapping` | ChartMapping | | 全グラフ |
| `bars` | string[] | | **`combo` のみ**。棒にする系列 |
| `lines` | string[] | | **`combo` のみ**。線にする系列 |
| `legend` | `"top"｜"bottom"｜"right"｜"none"` | top | 全グラフ |
| `gap` | `"break"｜"zero"｜"skip"` | break | **`line` / `area` のみ**。欠損値の扱い |
| `topN` | number | 円は 8 / それ以外は無指定 | 上位 N + その他。円・ドーナツは系列、**カテゴリ軸のグラフでは行**を値の降順で N 件残し、残りを「その他」へ合計する。並びが値順になるので月次などには使わない |
| `axisDecimals` | boolean | false | 円以外のグラフ。値軸に小数の目盛りを許す。**既定は整数のみ**で、件数に `0.75` のような目盛りが出るのを防ぐ。率や平均を描くときだけ `true` |
| `valueFormat` | NumberFormat(`kind` 抜き。§7) | | ツールチップ・ドーナツ中央の書式 |
| `valueFormatRight` | NumberFormat(`kind` 抜き。§7) | | **複合のみ**。右軸(線)の系列だけに使う書式。**`valueFormat` を継承しない**(省略 = 素の数値)。金額と件数を並べる用途では継承が常に誤りになるため |

**ChartMapping**

```jsonc
"mapping": { "x": "年月", "seriesKey": "商談フェーズ", "value": "売上", "valueColumns": ["売上", "件数"] }
```

| キー | 説明 |
| :--- | :--- |
| `x` | X 軸(カテゴリ)列。省略 = 1 列目 |
| `valueColumns` | **ワイド形式**: 系列にする列。省略 = X 以外の数値列すべて |
| `seriesKey` | **ロング形式**: 系列キー列 |
| `value` | ロング形式の値列 / 円・ドーナツの値列。省略 = 最初の数値列 |

- **ワイド形式** = 1 行 1 カテゴリ、系列は列(`年月, 売上, 件数`)
- **ロング形式** = カテゴリ + 系列キー + 値の 3 列(`年月, フェーズ, 売上`)
- 系列が 8 を超えると「その他」へ自動集約。系列色はテーマ共通の固定パレット(個別指定不可)

### 6.4 `markdown`

| キー | 型 | 説明 |
| :--- | :--- | :--- |
| `markdown` | string | **本文**(このキー名。`text` ではない) |
| `fontSize` | `"small"｜"normal"｜"large"｜"xlarge"` | 文字サイズ |

- `sql` を設定すると本文の `{{列名}}` が**結果 1 行目**の値に、`{{rowCount}}` が行数に置換される
- `sql` が空なら**クエリを実行せず即描画**
- **埋め込み値に数値書式は適用されない。** 桁区切りが要るなら SQL 側で整形する
- `style` 属性は装飾系のみ許可(`color` / `background-color` / `text-align` / `font-size` /
  `font-weight` / `font-style` / `text-decoration` / `border` / `border-radius` / `padding` / `margin`)。
  `script` / `iframe` 等は除去される

## 7. FormatSpec(値の書式)

**`kind` の要否が場所で違う。**

| 使う場所 | `kind` |
| :--- | :--- |
| `table` の `columns[].format` | **必要**(`"number"｜"date"｜"text"`) |
| `kpi` の `format`、グラフの `valueFormat` | **不要**(数値固定) |

**NumberFormat**

| キー | 値 | 既定 |
| :--- | :--- | :--- |
| `thousandSep` | boolean | true |
| `decimals` | 0〜4 | 自動 |
| `rounding` | `"round"｜"floor"｜"ceil"` | round |
| `scale` | `"none"｜"thousand"｜"man"｜"million"` | none |
| `prefix` / `suffix` | string | |
| `percent` | boolean(×100 して %) | false |
| `negative` | `"minus"｜"triangle"` | minus |
| `zero` | `"zero"｜"blank"｜"dash"` | zero |

`scale: "man"` は `40800000` → `4,080万`。金額はこれだけで読みやすくなる。

**DateFormat**

```jsonc
{ "kind": "date", "pattern": "YYYY/MM/DD" }
```

`pattern`: `YYYY/MM/DD` / `YYYY-MM` / `M/D` / `M月D日` / `YYYY/MM/DD(ddd)` / `YYYY/MM/DD HH:mm`

> NULL(空文字)とゼロは区別される。NULL は `-`、ゼロは既定で `0`。

## 8. SQL の制約(プラグイン・サブセット)

`FROM` には `APP<アプリ番号>` を書く。**フィールドはフィールドコード**で指定する
(ラベル「顧客No.」に対してコードが `顧客No_` のように異なる場合がある。
`ksql_describe_app` で必ず確認する)。

### 使えない構文 — CLI / MCP では動くがペインではエラー

| 構文 | ペインでの結果 |
| :--- | :--- |
| `APP4149@prod`(profile 指定) | `PARSE_ERROR` |
| `LAPP_案件管理@prod`(論理アプリの profile 指定) | エラー(ブラウザに profile は無い) |
| `IMPORT CSV` / `IMPORT JSON` | 使用不可(ライブラリの境界外) |
| `EXPLAIN UPDATE` など DML の `EXPLAIN` | 使用不可(同上) |
| `UPDATE … VALIDATE ONLY` などの DML 事前検証 | 使用不可(同上) |
| `INSERT` / `UPDATE` / `DELETE` | `READ_ONLY_VIOLATION` |

**使えるもの**: **`LAPP_<名前>`(論理アプリ参照。`logicalApps` に定義があるもの。未定義は名前入りエラー)**、`WITH`(CTE)、`UNION`、`SHOW` / `DESCRIBE`、サブテーブル仮想表 `APP100$明細`、
`VALIDATE APP<番号>`(入力規則違反の洗い出し)、
**`;` 区切りの複文・`CREATE TEMP TABLE` / `SET` / `DECLARE` / `ASSERT`**。

> **複文が書ける。****描画されるのは最後に結果セットを返した文**で、
> `CREATE TEMP TABLE` / `SET` / `DECLARE` は結果を作らない。
> 構成比(`SET @total = (SELECT …)`)や Top N + その他がこの形で書ける。
>
> **一時テーブルは閲覧者のブラウザのメモリに載る。**1 表あたり既定 10,000 行
> (`options.tempTableMaxRows` で 500〜50,000。超過は常にエラー)、同時 16 表まで、
> 寿命は**そのペインの 1 回の実行内だけ**。ペインをまたいだ共有はできない。

### 文法上の注意

- **SQL に書くのはフィールドコード。見せる名前はラベル。**
  kintone はコードとラベルが一致しないことがある(SFA パックの `顧客No_` ↔ 「顧客No.」)。
  表の見出し・グラフの凡例・KPI はすべて**結果の列名**を出すため、コードのまま書くと
  内部名が閲覧者に見える。**両者が違うときは `AS` でラベルを付ける。**

  ```sql
  SELECT 顧客No_ AS `顧客No.`, 金額 AS 受注金額 FROM APP100
  ```

  - ラベルに**記号・空白**があればバッククォートで囲む(`顧客No.` の `.` など)
  - ラベルが**日本語だけなら結果列名もそのまま**。何も気にしなくてよい
  - ラベルに**英数字が含まれると結果列名は小文字化**される
    (`` AS `顧客No.` `` → 列名 `顧客no.`)。表示は書いたとおり出る(`displayName`)が、
    **`columns` / `totals` / `mapping` には `ksql_query` が返した小文字の列名**を書く
- **相対日付**(`THIS_MONTH()` 等)は WHERE 専用。kintone 側へ押し下げられ取得件数が減る。
  **`JOIN` を含むクエリでも使える**(`AND` でつなげば複数アプリへ分散して渡る)。
  ただし **`LEFT`/`RIGHT JOIN`・アプリをまたぐ `OR`・CTE を JOIN の入力にした形**は取得前エラー
- **`DATE_ADD` は `DATE_ADD(列, n, '単位')`**(単位は `YEAR` / `MONTH` / `DAY`。減算は負数)。
  `DATE_SUB` と `INTERVAL` 構文は非対応。月・年の加減算は**結果の日が無ければ月末へ丸める**
  (`'2026-01-31'` の 1 か月後は `2026-02-28`)。**丸めが起きると往復は戻らない**
  (`1/31` → `2/28` → `1/28`)。月の比較は `YEAR(列) * 12 + MONTH(列)` が素直
- **ユーザー選択・作成者・更新者・チェックボックス・複数選択に `=` は使えない**。`in` / `not in` を使う
- **ドロップダウン・ラジオボタンは = でも動くが押し下げされない。in ('A') を使うと取得件数が減る**
- **数値の >= / <= は JOIN 内で押し下げされない**。売上 > 4999999 のように厳密比較へ書き換える
- `GROUP BY` に**集計エイリアスは使えない**(`ORDER BY` には使える)。式で書くのが安全
- ウィンドウ関数は `ROW_NUMBER()` / `RANK()` / `DENSE_RANK()` のみ。
  `OVER (…)` と `AS 別名` が必須で、**集計・GROUP BY と同じ SELECT には書けない**(CTE で分ける)
- 全体比 % は**単文では出せない**(`SUM(...) OVER ()`・集計内スカラーサブクエリとも非対応)。`ROLLUP` による小計・総計は使える
- **集計は fail-closed** — 取得上限に達するとエラーになる。WHERE で絞るか `maxRecords` を上げる。
  **明細は打ち切って表示**され、ペインに警告が出る(線引きはエンジンが行う)

詳細は [ダッシュボードレシピ集](./ダッシュボードレシピ集.md)。

## 9. バリデータが検査すること / しないこと

インポート時に検証されるのは**構造だけ**。**通ったからといって表示できるとは限らない。**

### 検査する

- `schemaVersion === 2` / `edition === "pro"`
- `views` / `common` がオブジェクトであること
- `layout[]` の `i` が非空文字列かつ**同一 layout 内で重複なし**、`x,y,w,h` が **0 以上の整数**
  (`w`/`h` は 1 以上)、**`x + w ≤ 60`**・**`y + h ≤ 2000`**
- `panes[]` が **12 枚以下**、`id` が非空かつ**重複なし**、`type` が既定の 11 種
- `sql` が文字列(`markdown` 以外は非空)
- `theme` / `source` / `refreshSec` / 各 boolean の型
- `options` がオブジェクトであること + **既知キーの形**:
  `bars` / `lines` = 文字列配列、`rules` / `columnGroups` / `refLines` = オブジェクトの配列、
  `columns` / `mapping` / `kpi` / `valueFormat` / `valueFormatRight` = オブジェクト、
  `maxRecords` / `tempTableMaxRows` / `topN` / `valueMax` / `valueMin` / `maxTiles` /
  `categoryWidth` = 有限数値、`markdown` = 文字列

### 検査しない ← 事故はここで起きる

| 項目 | 実際の挙動 |
| :--- | :--- |
| **`layout[].i` と `panes[].id` の対応** | ペインに対応する `layout` が無ければ**自動配置で描画**され、意図した位置にならない。余分な `layout` は無視される |
| `options` の**未知キー** | 誤ったキー名は**黙って無視**される(既知キーの形違いはエラーになる。§9 検査する) |
| `options` の**値の範囲** | `maxRecords` 等は範囲を検査せず、実行時に 500〜50,000 へ丸める |
| SQL の構文・フィールドの実在 | 保存後、一覧画面のペインで初めてエラーになる |
| ペイン同士の重なり | 重なって描画される |
| 参照する列名(`columns` / `mapping` / `totals` の列) | 結果に無い列は無視される |

**保存サイズの上限は 256KB**(80% で警告、超過で保存不可)。

## 11. 反映方法

REST API でプラグイン設定を読み書きする方法は**存在しない**
(`/k/v1/app/plugins.json` は `id` / `name` / `enabled` のみ返す)。
反映は設定画面から行う。

1. アプリの設定 → プラグイン → kSQL Dashboard Pro の **設定**
2. **ツール** → **インポート** で JSON を選択(検証に失敗した場合、既存設定は変更されない)
3. **保存**(`deployOnSave` が有効なら運用環境への反映まで自動)

現在の設定を JSON として取り出すには **エクスポート**を使う。

### 取り込みは 2 通りある

| | 対象 | 使いどころ |
| :--- | :--- | :--- |
| **インポート** | **設定を全置換**(`views` / `common` / `deployOnSave` すべて) | 環境を丸ごと移す |
| **このビューへ取り込む** | **編集中のビューだけ** | 配布ファイルを一覧ごとに割り当てる |

**全置換しかないと、2 つのダッシュボードを別々のビューへ配れない。**
1 本目を入れたあとに 2 本目を入れると、1 本目が消えるため。

「このビューへ取り込む」の挙動:

- ファイルに入っているダッシュボードのうち、**ペインを持つもの**が候補になる(`common.view` と `views` の各エントリー)
- 候補が **1 つならそのまま**取り込む。**複数あれば選択**させる
- 取り込み先が個別ビューなら `source` を `individual` にする(`共通` のままだと反映されないため)
- 取り込み先の `enabled` と `initialCollapsed` は**引き継ぐ**
- **元に戻す**で取り消せる

> 選択肢の見出しには**名前・ペイン数・先頭のペイン名**を出す。
> ビュー ID は書き出した環境のもので、取り込む側には存在しないことが多く、ID だけでは選べないため。
