# settings/ — 生成した設定 JSON の置き場

## ルール

- **固定名で上書き保存**する。履歴は git の diff で追う(日時付きファイル名を増やさない)
- **git が正** — 設定画面(GUI)で直したら、エクスポートしてここへ戻してコミットする。
  エクスポートのファイル名(`ksql-dashboard-pro-appNNNN-日時.json`)のままにせず、
  固定名へリネームする
- 常に**封筒形式**。`date` は取り込み・更新のたびに変わるが、それが「いつの版か」の記録になる

## フォルダー構成

アプリが 1〜2 個ならフラットでよい:

```
settings/
└─ 案件管理-営業ダッシュボード.json
```

増えたら**アプリ名のフォルダー**で分ける:

```
settings/
├─ 案件管理/
│   ├─ app.md                    ← アプリ番号(環境別)・対象一覧・メモ
│   ├─ 共通ダッシュボード.json     ← common.view に書いた設定
│   ├─ 【全社】ダッシュボード.json  ← 一覧(ビュー)単位の設定。ファイル名 = ダッシュボード名
│   └─ archive/                  ← 廃止した設定(消さずに退避)
└─ 顧客管理/
    └─ 顧客分析.json
```

- **フォルダー名はアプリ名**。アプリ番号は入れない(番号は環境で変わる。番号は
  app.md と封筒の `appId` が持つ)
- テスト環境と本番環境の差は、フォルダーを分けるのではなく**論理アプリ名
  (`LAPP_<名前>` + `logicalApps`)の対応表差し替え**で 1 ファイル運用にするのを推奨
